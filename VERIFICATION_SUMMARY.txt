SERVICE ARCHITECTURE
================================================================================

BEFORE (Monolith):
  server.js (9,347 lines)
  ├─ HTTP API handlers
  ├─ WebSocket server
  ├─ Background jobs
  ├─ Database init
  └─ Everything coupled together

AFTER (Decomposed):
  Message Bus (central communication hub)
         ↓
  ┌──────┼──────┐
  ↓      ↓      ↓
  API    WS    Worker
  Service Service Service
  (REST) (Chat) (Jobs)

Benefits:
  • Scale each independently
  • Isolate failures
  • Deploy separately
  • Handle load better
  • Clearer code organization

================================================================================
DEPLOYMENT OPTIONS
================================================================================

1. SINGLE PROCESS (Default - Works now)
   node server-orchestrated.js
   → All services in one process
   → No infrastructure needed
   → Perfect for development

2. HYBRID (Recommended for production)
   Terminal 1: npm start                    # API + WebSocket
   Terminal 2: ENABLE_HTTP_API=false npm start  # Worker only
   → Separate long-running jobs
   → Simple to deploy
   → Easy to scale workers

3. DISTRIBUTED (For scale-up)
   With Redis message bus
   Pod 1: API service (replicated)
   Pod 2: WebSocket service
   Pod 3+: Worker services (auto-scale)
   → True microservices
   → Kubernetes ready
   → Infinite scalability
